# agent_format

형식·완전성 검사 (규칙). 플레이스홀더(TBD)·필수절·칸 값·글꼴·파일명·약어. LLM 없이 동작.

## 공개 인터페이스
`__init__.py`에서 export하는 것만 외부에서 쓴다:

`PlaceholderChecker` `CompletenessChecker` `FieldPresenceChecker` `FontSizeChecker`
`FilenameChecker` `AbbrevChecker` `RefListChecker` `TextPatternChecker` `SignatureSpec`.

**검사할 것을 하나도 못 받으면 지적 0건이 아니라 미검토(INFO)를 낸다.** 필수 절
목록이 비었거나, 볼 칸이 없거나, 파일명 규칙이 없거나, 약어 장절을 못 찾은 경우가
그것이다. 조용한 0건은 "검사했더니 이상 없음"과 화면에서 구분되지 않는다.

### FilenameChecker

제출 파일명이 팀 규칙에 맞는가. 형식은 코드가 정하지 않는다 — 정규식을 주입받는다.
확장자는 빼고 잰다.

```python
FilenameChecker(
    pattern=r"[^_]+_Rev\.\d+_.+",            # 계통문서번호_버전_문서명 (EV3)
    example="Z11008-940VD-011C_Rev.08_RVVR for ESF-CCS for SKN56",
    forbidden=("사본", "최종"),               # 임시본·중복본 표시
).check(doc)
```

형식 불일치는 MAJOR, 금지 표시는 MINOR. 정규식이 깨졌으면 지적이 아니라 미검토다 —
지적으로 내면 멀쩡한 파일명이 전부 틀린 것으로 뜬다.

### AbbrevChecker

약어 목록 장절과 본문을 **양방향**으로 대조한다. 둘 다 MINOR.

```python
AbbrevChecker(sections=("약어", "abbrevia"), ignore=("PDF",)).check(doc)
```

| 방향 | 뜻 | 목록을 읽는 방식 |
|---|---|---|
| 본문 → 목록 | 쓴 약어가 목록에 없다 | 장절 안의 **모든** 대문자 토큰을 등록으로 본다 |
| 목록 → 본문 | 목록 약어가 안 쓰인다 | 각 줄의 **첫** 토큰만 항목으로 본다 |

두 방향의 오탐 성격이 반대라 읽는 방식이 다르다. 미등록은 시끄러운 쪽이라 등록
판정을 넓게 잡아 조용히 하고, 미사용은 설명문의 토큰을 항목으로 세면 없는 약어를
지우라고 하게 되므로 좁게 잡는다.

후보 규칙은 `data/` 실문서 넷으로 재서 정했다(미등록 후보 907 → 423):

| 규칙 | 왜 | 효과 |
|---|---|---|
| 2~8글자 **순수 대문자** | 숫자를 허용하면 문서번호·요건 ID 가 다 후보가 된다 (`Z11008` `FR0050` `VR01`) | 907 → 468 |
| 줄 전체가 대문자면 건너뛴다 | 표지·목차·머리행이 통째로 대문자라 `OF` `BY` `ALL` 이 후보가 된다. 약어 장절 안에서는 안 쓴다 | 468 → 423 |
| 여러 건을 **한 지적**으로 | 낱개면 문서 하나에서 174건이 쏟아져 다른 검사까지 파묻는다 | 174건 → 1건 |
| 하이픈 뒤가 숫자면 문서번호 | `SST-26-999` `RN-26-999` — 하이픈이 토큰을 끊어 앞머리가 남는다 | 서식 5건이 조용해짐 |
| 문서 안에서 **소문자로도 쓰이면** 약어가 아니다 | `SERVER`/`server` `AND`/`and` `TRUE`/`true`. 무시목록으로는 끝이 없어 문서 자신에게 묻는다 | 98 → 49 |

한글 전문용어는 형태로 못 가려서 안 잡는다.

**못 재는 상황을 셋으로 가른다** (2026-08-20, 실측 오탐 279건 뒤):

| 상황 | 무엇을 내나 |
|---|---|
| 약어 절이 없고 본문에도 약어가 없다 | 조용히 0건 — 대조할 것이 없었고 어긋난 것도 없다 |
| 약어 절이 없는데 본문은 약어를 쓴다 | 미검토 — 검토자가 알아야 한다 |
| 약어 절은 찾았는데 목록이 안 읽혔다 | 미검토 — 빈 목록으로 재면 본문 대문자가 전부 "미등록"이 된다 |

첫 칸이 없으면 약어를 안 쓰는 한글 서식(체크리스트·을지·시험의뢰서)마다 미검토
카드가 떠서, 매번 뜨는 카드가 **진짜 미검토까지 함께 무시하게** 만든다.

### RefListChecker

참조문서 목록 ↔ 본문 인용 **양방향**. 대조 단위는 문서명이 아니라 **절 번호**다 —
같은 문서를 부르는 이름이 문서마다 달라 이름으로는 대조가 안 된다.

```
3.0 References              ← 참조 절 (제목이 References/참조문서로 끝난다)
  3.1 Regulations           ← 묶음. 항목이 아니다
    3.1.1 NUREG-0800, ...   ← 항목
본문: "... (reference 3.1.1)"  ← 인용
```

| 방향 | 뜻 | 등급 |
|---|---|---|
| 본문 → 목록 | 목록에 없는 항목을 인용한다 | MAJOR |
| 목록 → 본문 | 목록에 있는데 인용되지 않는다 | MINOR |

**묶음 절은 번호로 가린다**(자식 유무가 아니라). PDF 책갈피 깊이가 문서마다
들쭉날쭉해서 같은 구조가 어디서는 부모-자식, 어디서는 형제로 들어온다.

**목록을 거의 못 읽었으면(2건 미만) 지적하지 않는다.** 실측에서 책갈피가 얕은 PDF 가
항목을 0건 내놨고, 그대로 대조하면 멀쩡한 인용이 전부 "목록에 없는 문서"로 뜬다.

### FieldPresenceChecker

산출물 양식 하나를 받아 그 문서의 칸들을 판정한다. 기준은 주입받는다 —
이 모듈은 팀 이름도 문서 이름도 모른다.

```python
FieldPresenceChecker(
    fields=[FieldSpec(name="성적서번호", labels=("성적서번호",),
                      pattern=r"SST-\d{2}-\d{3}-C\d+", required=True)],
    fixed_text=["슈어소프트테크㈜"],
    signatures=[SignatureSpec(role="시험실무자", placeholder="성명")],
).check(doc)
```

판정하는 규칙 어휘:

| 어휘 | 위반이면 | 예 |
|---|---|---|
| `required` | 칸이 비었다 | MAJOR |
| `pattern` | 정규식 전체 불일치 | MAJOR |
| `format: date` | `2026. 01. 05.` 아님, 또는 달력에 없는 날 | MAJOR |
| `format: date_range` | 형식 위반 또는 시작 > 종료 | MAJOR |
| `equals` | 정해진 문구와 다름 (공백 무시) | MAJOR |
| `select: one` | 0개 또는 2개 이상 선택 | MAJOR |
| `fixed_text` | 양식 고정 문구가 문서에 없음 (공백 무시) | MAJOR |
| `signatures` | placeholder 가 그대로 남음 = 미작성 | MAJOR |

**못 찾은 것은 지적이 아니다.** 라벨맵이 문서와 어긋났을 수 있으므로
`unreviewed=True` 인 INFO 로 낸다 — "검사 못 함"과 "지적 0건"을 섞지 않는다.
모르는 `format` 값도 조용히 통과시키지 않고 미검토로 낸다.
